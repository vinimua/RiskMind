# 1 报告框架

## 1.1 项目目标

本报告描述模拟机构“澄信数字金融研究环境”中 `credit_v3` 的 `v3.1` 版本，服务于**个人消费信贷首次授信**。目标是审批前风险排序；分数不应单独替代授信策略、人工复核或监管要求。模型输入、适用人群、标签与样本窗口均按本报告冻结，为异常调查提供可追踪的**历史基线**，不是现时生产事实。

本次版本的主要变更为：升级征信数据映射，扩大合作渠道；保留与v3.0并行回放。与前一报告版本（v3.0）的比较需固定相同客群和成熟标签定义，否则 KS、AUC 的差值不可直接归因为模型本身。

## 1.2 模型适用范围

适用范围：个人消费信贷首次授信，且具备完整的申请/账户主键、评分时间戳、特征事件时间和合法数据使用授权。非适用场景包括企业或个人身份混用、目标产品之外的转介申请、未获授权的数据共享，以及标签观察不完整却需要立即确认真实违约表现的场景。

**限制条件**：合作渠道名单动态变化，渠道分群样本可能低于稳定阈值。任何跨渠道、跨地区或新产品使用均需进行分群回测和独立核验，不因模型名相近而继承旧批准范围。

# 2 数据获取和分析

## 2.1 数据来源

数据源按模拟合同分为业务申请/账户台账 `sim_applications_credit_v3`、授信与还款快照 `sim_repayment_credit_v3`、历史特征明细 `sim_features_credit_v3` 和标签快照 `sim_labels_credit_v3`。`application_id` 或 `account_id` 与评分时点共同构成回放键。每张表需记录批次号、事件时间、入库时间、源系统版本及脱敏后的记录标识。

开发样本为 **148,500 条**；口径要求评分当时可知的数据才可入模。标签是“**放款后30日内DPD≥7**”，观察窗口 **30 天**；未满足观察窗口的样本保持 `UNMATURED`，不得当作正常好样本。为避免结果泄漏，开发切分以申请/评分月份为主，关联客户不得跨训练和验证集重复出现。

## 2.2 数据预处理

主要流程是：核对主键与事件时间 → 保留评分时可见版本 → 统一缺失标记 → 金额冲正及撤销处理 → 标签成熟校验 → 按客群/渠道分层统计。收入、授信额度、账单日期等异常值不能一概用数值零填充；确实需要零值时应有独立状态标记。

质量门禁包含主键唯一率、原始记录数与特征拼接数对账、字段缺失率变化、关联键匹配率和 T+N 回补窗口。上线特征采用冻结特征定义；观察到异常时先检查数据质量和版本一致性，再讨论模型重新训练。

## 2.3 数据统计特征与变量定义

| 核心特征 | 标准计算口径 | 模型使用 |
|---|---|---|
| `apply_cnt_30d` | 以申请事件发生时间计算近30自然日有效申请次数，排除撤销与测试申请 | 评分关键驱动 |
| `credit_query_cnt_6m` | 以征信返回时间倒推6个月查询次数，保持机构去重规则 | 评分关键驱动 |
| `debt_ratio` | 有息负债月供/经核验月收入，缺失收入不得直接置零 | 辅助及分群监控 |
| `credit_history_months` | 最早有效授信账户到申请日的月龄，删去测试账户 | 辅助及分群监控 |

这些定义属于 `v3.1` 的冻结业务说明，不等于其他版本或其他模型的通用特征定义。若两版同名字段口径改变，必须按字段契约和可核验历史数据分别计算差异。

## 2.4 数据划分

| 集合 | 样本数 | 主要作用 |
|---|---:|---|
| 训练集 | 98,010 | 变量筛选与模型拟合，不用于最终独立验收 |
| 内部验证集 | 28,215 | 模型选择与参数检查 |
| 跨时间验证集 | 22,275 | 分布迁移、效果与校准检查 |
| 总计 | 148,500 | 三集合客户或账户级隔离 |

跨时间集只使用已成熟标签；若某月成熟率显著不足，性能数字必须同时报告有效样本量及标签成熟状态。分群样本稀疏时只报告不确定性，不用总样本数代替各群的统计显著性。

# 3 模型设计

## 3.1 模型选型

采用 **LightGBM**。选择依据包括成熟样本的 KS/AUC、稳定性、特征可解释性、性能与推理成本及工程复现能力。候选方法应与朴素基线比较；不将单次验证集优势描述成对新客群的持续有效性保证。

## 3.2 模型架构

正式逻辑为：授权数据快照 → 固定特征时间点 → 特征版本与取数质量校验 → LightGBM → 风险排序输出 → 策略服务按独立规则使用。回放测试同时保留 `model_id=credit_v3`、`model_version=v3.1`、特征配置版本及评分时间；同一客户不同时间评分属于不同事件。

## 3.3 特征工程与上线一致性

- **`apply_cnt_30d`**：以申请事件发生时间计算近30自然日有效申请次数，排除撤销与测试申请；与开发基线按相同实体、时间与缺失值规则比较。
- **`credit_query_cnt_6m`**：以征信返回时间倒推6个月查询次数，保持机构去重规则；与开发基线按相同实体、时间与缺失值规则比较。
- **`debt_ratio`**：有息负债月供/经核验月收入，缺失收入不得直接置零；与开发基线按相同实体、时间与缺失值规则比较。
- **`credit_history_months`**：最早有效授信账户到申请日的月龄，删去测试账户；与开发基线按相同实体、时间与缺失值规则比较。

离线和在线计算的事件时间、时区、取数回补及缺失编码应逐字段对账。模型部署使用不可变制品摘要，特征服务版本通过白名单固定。发生效果异常时应核验“相同版本、相同输入是否能复现相同输出”，避免把集成缺陷误判为自然退化。

# 4 模型评估

## 4.1 评估口径

KS、AUC 为已成熟标签样本的区分能力指标；PSI 为分布差异指标，须指定基准分布与分箱方案。当前报告数字均为合成离线测试值，**不是告警阈值**。小样本分群需报告置信区间或明确样本不足的限制。

## 4.2 主要结果

| 指标类别 | 指标 | 模拟跨时点结果 | 计算范围 | 解释限制 |
|---|---|---:|---|---|
| 模型效果 | KS | 0.428 | 成熟标签样本 | 开发期基线；实际告警由独立规则决定 |
| 模型效果 | AUC | 0.777 | 成熟标签样本 | 按分群核验一致性 |
| 稳定性 | Score PSI | 0.055 | 开发期基准评分分布 | 不能从PSI直接推断效果退化 |

额外核查：针对高风险分群抽取固定样本回放；若出现明显违约标签滞后，禁止输出“模型已经退化”的确定结论。不同报告版本之间的比较必须首先确认标签、数据窗口与评估客群一致。

## 4.3 结果分析与已知风险

当前模拟结果支持该版本作为个人消费信贷首次授信的风险排序研究基线；不支持跨人群直接使用，也不支持仅凭历史基线决定线上处置。最值得持续监测的风险是：合作渠道名单动态变化，渠道分群样本可能低于稳定阈值。建议将总体指标、分渠道指标、标签成熟率、关键特征 PSI、数据延迟和版本校验分别呈现。

**调查使用约束**：任何当前告警都应通过授权的事实检索和计算工具读取最新数据；本报告只用于确定应核验什么、计算口径是什么、历史限制是什么。即使某次历史案例复算成功，也不能当作新的当前案件根因证据。
