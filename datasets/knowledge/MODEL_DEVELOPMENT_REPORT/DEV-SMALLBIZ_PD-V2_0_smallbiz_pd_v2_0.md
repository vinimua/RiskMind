# 1 报告框架

## 1.1 项目目标

本报告描述模拟机构“澄信数字金融研究环境”中 `smallbiz_pd` 的 `v2.0` 版本，服务于**小微企业经营贷**。目标是小微企业12月违约概率排序；分数不应单独替代授信策略、人工复核或监管要求。模型输入、适用人群、标签与样本窗口均按本报告冻结，为异常调查提供可追踪的**历史基线**，不是现时生产事实。

本次版本的主要变更为：企业经营流水及发票因子初版。与前一报告版本（无相邻前版）的比较需固定相同客群和成熟标签定义，否则 KS、AUC 的差值不可直接归因为模型本身。

## 1.2 模型适用范围

适用范围：小微企业经营贷，且具备完整的申请/账户主键、评分时间戳、特征事件时间和合法数据使用授权。非适用场景包括企业或个人身份混用、目标产品之外的转介申请、未获授权的数据共享，以及标签观察不完整却需要立即确认真实违约表现的场景。

**限制条件**：行业周期性和财报补报可能使标签延迟。任何跨渠道、跨地区或新产品使用均需进行分群回测和独立核验，不因模型名相近而继承旧批准范围。

# 2 数据获取和分析

## 2.1 数据来源

数据源按模拟合同分为业务申请/账户台账 `sim_applications_smallbiz_pd`、授信与还款快照 `sim_repayment_smallbiz_pd`、历史特征明细 `sim_features_smallbiz_pd` 和标签快照 `sim_labels_smallbiz_pd`。`application_id` 或 `account_id` 与评分时点共同构成回放键。每张表需记录批次号、事件时间、入库时间、源系统版本及脱敏后的记录标识。

开发样本为 **47,200 条**；口径要求评分当时可知的数据才可入模。标签是“**观察期内90日逾期**”，观察窗口 **90 天**；未满足观察窗口的样本保持 `UNMATURED`，不得当作正常好样本。为避免结果泄漏，开发切分以申请/评分月份为主，关联客户不得跨训练和验证集重复出现。

## 2.2 数据预处理

主要流程是：核对主键与事件时间 → 保留评分时可见版本 → 统一缺失标记 → 金额冲正及撤销处理 → 标签成熟校验 → 按客群/渠道分层统计。收入、授信额度、账单日期等异常值不能一概用数值零填充；确实需要零值时应有独立状态标记。

质量门禁包含主键唯一率、原始记录数与特征拼接数对账、字段缺失率变化、关联键匹配率和 T+N 回补窗口。上线特征采用冻结特征定义；观察到异常时先检查数据质量和版本一致性，再讨论模型重新训练。

## 2.3 数据统计特征与变量定义

| 核心特征 | 标准计算口径 | 模型使用 |
|---|---|---|
| `cashflow_volatility_90d` | 90日净流入相对波动，跨账户去重并固定时区 | 评分关键驱动 |
| `invoice_ratio_180d` | 180日开票金额与核验营业收入的比例，含补报标识 | 评分关键驱动 |
| `business_age_months` | 营业执照设立月至评分月的经营月龄 | 辅助及分群监控 |
| `guarantee_type` | 按已批准的担保分类字典编码，不允许推理补全 | 辅助及分群监控 |

这些定义属于 `v2.0` 的冻结业务说明，不等于其他版本或其他模型的通用特征定义。若两版同名字段口径改变，必须按字段契约和可核验历史数据分别计算差异。

## 2.4 数据划分

| 集合 | 样本数 | 主要作用 |
|---|---:|---|
| 训练集 | 31,152 | 变量筛选与模型拟合，不用于最终独立验收 |
| 内部验证集 | 8,968 | 模型选择与参数检查 |

跨时间集只使用已成熟标签；若某月成熟率显著不足，性能数字必须同时报告有效样本量及标签成熟状态。分群样本稀疏时只报告不确定性，不用总样本数代替各群的统计显著性。

# 3 模型设计

## 3.1 模型选型

采用 **XGBoost**。选择依据包括成熟样本的 KS/AUC、稳定性、特征可解释性、性能与推理成本及工程复现能力。候选方法应与朴素基线比较；不将单次验证集优势描述成对新客群的持续有效性保证。

## 3.2 模型架构

正式逻辑为：授权数据快照 → 固定特征时间点 → 特征版本与取数质量校验 → XGBoost → 风险排序输出 → 策略服务按独立规则使用。回放测试同时保留 `model_id=smallbiz_pd`、`model_version=v2.0`、特征配置版本及评分时间；同一客户不同时间评分属于不同事件。

## 3.3 特征工程与上线一致性

- **`cashflow_volatility_90d`**：90日净流入相对波动，跨账户去重并固定时区；与开发基线按相同实体、时间与缺失值规则比较。
- **`invoice_ratio_180d`**：180日开票金额与核验营业收入的比例，含补报标识；与开发基线按相同实体、时间与缺失值规则比较。
- **`business_age_months`**：营业执照设立月至评分月的经营月龄；与开发基线按相同实体、时间与缺失值规则比较。
- **`guarantee_type`**：按已批准的担保分类字典编码，不允许推理补全；与开发基线按相同实体、时间与缺失值规则比较。

离线和在线计算的事件时间、时区、取数回补及缺失编码应逐字段对账。模型部署使用不可变制品摘要，特征服务版本通过白名单固定。发生效果异常时应核验“相同版本、相同输入是否能复现相同输出”，避免把集成缺陷误判为自然退化。

# 4 模型评估

## 4.1 评估口径

KS、AUC 为已成熟标签样本的区分能力指标；PSI 为分布差异指标，须指定基准分布与分箱方案。当前报告数字均为合成离线测试值，**不是告警阈值**。小样本分群需报告置信区间或明确样本不足的限制。

## 4.2 主要结果

| 指标类别 | 指标 | 模拟跨时点结果 | 计算范围 | 解释限制 |
|---|---|---:|---|---|
| 模型效果 | KS | 0.362 | 成熟标签样本 | 开发期基线；实际告警由独立规则决定 |
| 模型效果 | AUC | 0.731 | 成熟标签样本 | 按分群核验一致性 |
| 稳定性 | Score PSI | 0.071 | 开发期基准评分分布 | 不能从PSI直接推断效果退化 |

额外核查：针对高风险分群抽取固定样本回放；若出现明显违约标签滞后，禁止输出“模型已经退化”的确定结论。不同报告版本之间的比较必须首先确认标签、数据窗口与评估客群一致。

## 4.3 结果分析与已知风险

当前模拟结果支持该版本作为小微企业经营贷的风险排序研究基线；不支持跨人群直接使用，也不支持仅凭历史基线决定线上处置。最值得持续监测的风险是：行业周期性和财报补报可能使标签延迟。建议将总体指标、分渠道指标、标签成熟率、关键特征 PSI、数据延迟和版本校验分别呈现。

**调查使用约束**：任何当前告警都应通过授权的事实检索和计算工具读取最新数据；本报告只用于确定应核验什么、计算口径是什么、历史限制是什么。即使某次历史案例复算成功，也不能当作新的当前案件根因证据。
